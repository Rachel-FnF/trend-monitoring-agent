문제가 생겼어요 — 상황별 해결

💻 명령을 실행하는 법 (아래 카드들에서 사용)
① 바탕화면에서 이 프로젝트 폴더(trend-monitoring-agent)를 연다 → ② 폴더 위쪽 주소창을 클릭하고 powershell이라고 입력 후 엔터 → ③ 검은 창이 뜨면 아래 명령을 복사해 붙여넣고(마우스 우클릭=붙여넣기) 엔터.

Q. 시트에 오늘 새 줄이 없어요

  1. 오늘 아침 8시에 컴퓨터가 꺼져 있었다면 → 그게 원인이에요. 아래 명령으로 지금 한 번 돌려주세요 (10~25분 걸림): 
    venv\Scripts\python.exe src\core\run_daily.py
  2. 끝나면 시트를 새로고침해서 새 줄이 생겼는지 확인. 몇 번을 다시 돌려도 중복으로 쌓이지 않으니 걱정 마세요.
  3. 그래도 안 되면 → 아래 "잘 모르겠어요" 카드로.

Q. "캐릿 로그인이 풀렸다"고 해요 (수집 실패)

캐릿은 유료 사이트라 가끔 로그인이 풀립니다. 이때만 사람 손이 한 번 필요해요.

  1. 아래 명령을 실행 → 브라우저가 저절로 열리며 로그인을 진행합니다: 
    venv\Scripts\python.exe src\service\setup_profile.py
  2. "인증번호를 입력하라"고 하면 → 캐릿 계정 이메일로 온 숫자 코드를 확인하고, 프로젝트 폴더 안에 .otp라는 이름의 파일을 만들어 그 숫자만 적어 저장하세요. (메모장에서 저장 시 파일 이름을 ".otp" 따옴표 포함으로 저장하면 됩니다)
  3. "기기가 꽉 찼다"는 화면이 나오면 → 화면에서 안 쓰는 기기를 삭제하고 계속 진행.
  4. 끝나면 위의 "시트에 새 줄이 없어요" 카드의 명령으로 오늘 치를 한 번 돌려주세요.

⚠️ 진행 중에 열린 브라우저 창을 강제로 닫지 마세요 — 로그인이 저장되기 전에 날아갑니다.

Q. 잘 모르겠어요 / 다른 오류가 떠요

  1. 이 컴퓨터에 Claude Code(AI 도우미)가 설치되어 있어요. 프로젝트 폴더에서 Claude Code를 열고 /trend-status 라고 입력하면, AI가 스스로 검사하고 무엇이 문제인지·어떻게 고치는지 알려줍니다.
  2. 또는 그냥 한국어로 물어봐도 됩니다: "오늘 시트에 글이 안 올라왔어, 확인해줘"
  3. AI로도 해결이 안 되면 개발 담당자에게 src\data\run.log 파일(실행 기록)과 함께 문의하세요.

1

전달 패키지 — 파일을 어떤 형태로 주고받나

이 프로젝트는 "git에 있는 것"과 "git 밖에 있는 것"의 2트랙으로 넘겨야 한다. 비밀키·브라우저 프로필·예약작업·가상환경은 의도적으로 git 밖에 있고, 그중 일부는 새 PC에서 재생성해야 하지 복사하면 안 된다.

트랙 A — 코드 (git)

가장 깔끔한 형태는 git 저장소 그대로다. 원격 저장소 접근 권한을 주거나, 원격이 곤란하면 히스토리까지 담긴 단일 파일로 만들어 전달한다:

# 히스토리 포함 단일 파일 (받는 쪽: git clone trend-agent.bundle 폴더명)
git bundle create trend-agent.bundle --all

zip으로 폴더를 통째 복사해도 되지만, 그 경우 venv\·profile\은 반드시 빼고 보낼 것 — 어차피 새 PC에서 재생성해야 하는 것들이고, 특히 profile\(캐릿 세션)은 복사해도 기기 인증이 맞지 않다.

트랙 B — 비밀·데이터 패키지 (DM/USB 전용, 절대 git 금지)

파일내용필수?
.env캐릿 계정·Gemini 키·시트 ID (5-2절에 전체 키 설명)필수
gcp_sa.json구글 서비스계정 키 (시트 push 인증)필수
requirements.txt구 PC에서 venv\Scripts\pip.exe freeze > requirements.txt로 생성필수
trends.db누적 SQLite DB — 새로 시작해도 시트에는 기록이 남아있으므로 선택선택
trenddb_owner.txt수집자 이름표 — 없으면 새 PC에서 trenddb.py set-owner <이름> 1회선택
src\data\ 폴더 zip본문 캐시 10종 + 분석 캐시 — 가져가면 첫 실행 때 재수집·재분석(Gemini 비용) 절약권장

넘기지 않는 것 (새 PC에서 재생성)

  • venv\ — 파이썬 가상환경. requirements.txt로 재설치.
  • profile\ — 캐릿 Playwright 브라우저 프로필. 새 PC에서 setup_profile.py로 기기 등록부터 다시 (캐릿은 기기 4대 제한 + 이메일 OTP — 이관에서 제일 까다로운 단계).
  • Windows 예약작업 FF-Trend-Daily — 절대경로를 물고 있어 복사 불가. 4절의 명령으로 새로 등록.
인계 전 반드시 결정할 소유권 2가지 — ① 캐릿 유료 계정 명의(OTP가 계정 이메일로 오므로 계정이 바뀌면 프로필 셋업을 처음부터), ② 구글 시트·서비스계정의 편집 권한. 둘 다 새 담당자 소유로 옮기는 것을 권장한다 — 그래야 전임자 퇴사·계정 정지에도 시스템이 살아있다.
2

시스템 아키텍처

구조는 수집 → 분석 → 누적(시트)의 3층이다. 매일 08:00에 예약작업 하나(FF-Trend-Daily)가 run_daily.py 4단계를 순서대로 실행한다. 전 과정이 무인 실행된다.

run_daily.py의 4단계

  1. collect.py — 13소스 수집, 21일 윈도우 컷오프. 실패 시 전체 중단(대부분 캐릿 세션 만료).
  2. content_analyzer.py --all — article_items.collect_items()로 오늘의 글 목록을 만들고(수집 스냅샷 + 외부 소스 실시간 fetch → 정규화), 글별로 Gemini vision 분석. 캐시 hit는 자동 스킵.
  3. trenddb.py export — 분석 결과를 trends.db에 누적(upsert). DB는 영구 누적 — 삭제하지 않는다.
  4. sheets_push.py — 구글 시트에 새 글만 append. 기존 행은 절대 안 건드림.

2~4단계는 각각 try로 감싸져 있어 하나가 실패해도 나머지는 진행된다. 각 단계 exit 코드는 src\data\run.log에 남는다. 기술 상세(소스별 수집 방식·캐시 구조)는 CLAUDE.md 참조.

4

새 PC 셋업 체크리스트

  1. 코드 배치 — git clone(또는 bundle/zip 해제). 이후 명령은 모두 프로젝트 루트 기준.
  2. 파이썬 환경: 
    python -m venv venv
venv\Scripts\pip.exe install -r requirements.txt
venv\Scripts\playwright.exe install chromium
  3. 비밀 파일 배치 — 트랙 B로 받은 .env·gcp_sa.json을 프로젝트 루트에, (선택) trends.db·src\data\ 캐시도 제자리에.
  4. 캐릿 기기 등록 (제일 까다로움): venv\Scripts\python.exe src\service\setup_profile.py 실행 → 로그인 중 인증번호 요구 시 캐릿 계정 이메일의 코드를 프로젝트 루트에 .otp 파일로 저장(내용=숫자만) → 기기 슬롯 4개가 꽉 찼다면 기존 기기 삭제 먼저. 일반 크롬에서 로그인해도 소용없다 — 자동화가 쓰는 그 프로필(profile\)에서 등록해야 유효.
  5. 수동 테스트: venv\Scripts\python.exe src\core\run_daily.py → src\data\run.log에서 전 단계 exit=0 확인 → sheets_push.py --dry로 시트 연결 확인.
  6. 예약작업 등록 — 관리자 PowerShell에서 $ROOT만 실제 경로로: 
    $ROOT = "C:\Users\<사용자>\Agent\trend-monitoring-agent"
$PY = "$ROOT\venv\Scripts\python.exe"
schtasks /Create /F /TN FF-Trend-Daily /SC DAILY /ST 08:00 /TR "`"$PY`" `"$ROOT\src\core\run_daily.py`""
  7. 다음날 아침 검증 — 구글 시트 맨 아래에 오늘 날짜(DB등록일 칸)의 새 행이 있는지 확인. 정상이면 구 PC의 예약작업 삭제: schtasks /Delete /F /TN FF-Trend-Daily.
전제 조건: 예약작업은 PC가 켜져 있고 해당 계정으로 로그인된 상태여야 실행된다. PC를 꺼두면 그날 수집은 건너뛰지만, 21일 윈도우 덕에 다음 실행 때 놓친 글이 자동 보충된다.
5

커스터마이징 가이드 ★

새 팀에 맞게 손댈 가능성이 높은 순서로 정리했다. 모든 수정 후에는 run_daily.py 수동 1회 실행으로 검증하는 것을 권장. 직접 고치기 어려우면 Claude Code에 이 절의 해당 항목을 보여주며 요청하면 된다 — 예: "수집 시간을 아침 7시로 바꿔줘", "○○사이트를 새 소스로 추가해줘".

5-1. 업데이트 주기(실행 시각) 변경

주기는 코드가 아니라 Windows 예약작업에 있다. 시각만 바꾸려면:

schtasks /Change /TN FF-Trend-Daily /ST 07:00
  • 하루 2회 실행도 가능(예: 08:00 외에 /SC DAILY /ST 16:00으로 이름만 다른 작업 하나 더 등록). 분석은 URL 캐시, 시트는 append-only라 중복 비용·중복 행이 생기지 않는다 — 오히려 낮에 발행된 글을 그날 잡는 효과.
  • 현재 상태 확인: schtasks /Query /TN FF-Trend-Daily /V /FO LIST

5-3. 수집 윈도우·리밋 조정

수집 윈도우(며칠 치를 유지할지)는 src\core\collect.py와 src\service\article_items.py 상단의 같은 한 줄이 지배한다:

# 기본 = 오늘로부터 21일 전 (최근 3주)
SINCE_DATE = os.environ.get("SINCE_DATE") or (datetime.date.today() - datetime.timedelta(days=21)).isoformat()

days=21을 바꾸면(두 파일 모두) 수집·분석이 다루는 창이 함께 바뀐다. 줄이면 Gemini 비용·실행 시간 감소, 늘리면 놓친 글 보충 여지가 커진다. (DB·시트는 영구 누적이라 영향 없음.)

5-4. 새로운 사이트(소스) 추가 — 4단계

아키텍처상 새 소스는 수집층에만 손대면 된다. 분석·DB·시트는 자동으로 따라온다.

  1. 수집 모듈 작성 — src\service\<사이트>.py에 fetch_<사이트>(limit=15) 함수. 반환은 dict 리스트이고 최소 필드는 title · url · date(YYYY-MM-DD) · excerpt, 있으면 image · category. 맨땅에서 만들지 말고 가장 비슷한 기존 모듈을 복사해서 시작할 것:
    • RSS 제공 → gogumafarm.py 참고
    • 정적 HTML 리스팅 → insight.py · the_edit.py
    • 공개 JSON API → eyesmag.py
    • JS 렌더링 필요(SPA) → newneek.py (Playwright)
    • 사이트맵 기반 → fashionbiz.py
    본문이 리스팅에 없으면 기존 모듈들의 영구 캐시 패턴(src\data\<사이트>_body_cache.json, 캐시 hit면 스킵·miss만 fetch)을 그대로 따를 것 — 매일 도는 시스템이라 캐시 없으면 상대 서버에 민폐고 실행도 느려진다.
  2. src\core\collect.py 연결 — 기존 소스 블록(패션비즈·Vogue 부분)을 복사해 3곳 수정: ① try/except 수집 블록 추가(실패해도 전체가 죽지 않는 구조 유지), ② SINCE_DATE 필터 한 줄, ③ out dict의 counts와 본문에 키 추가. 주의: Playwright를 쓰는 소스는 캐릿 with 블록 밖에서 호출해야 한다(뉴닉 블록의 주석 참조).
  3. src\service\article_items.py 연결 — 상단 import 목록에 추가하고, 기존 소스처럼 normalize 블록(source명·날짜·발췌 300자·카테고리 매핑) 추가. 여기 등록돼야 분석기가 그 소스의 글을 분석하고 시트까지 올라간다 — 이 단계를 빼먹으면 수집만 되고 시트에 안 나온다.
  4. CLAUDE.md 문서 갱신 — 소스 표와 캐시 목록에 추가. AI 도구로 유지보수하는 프로젝트라 이 파일이 곧 명세서다. 이후 run_daily.py 1회 실행으로 검증.
팁: Claude Code에 "CLAUDE.md의 소스 표 형식대로 ○○사이트를 새 소스로 추가해줘"라고 요청하면 위 4단계를 한 번에 처리할 수 있다. 다만 2~3단계의 연결 지점이 맞는지 diff는 직접 확인할 것.

소스 제거는 반대로: collect.py·article_items.py의 해당 블록을 지우면 끝(모듈 파일은 남겨둬도 무해 — 네이버 데이터랩이 그 방식으로 비활성화돼 있다).

5-5. 시트 커스터마이징

  • 컬럼 규칙 — 자동 칸 A~N(제목·article_id·URL·카테고리·요약·토픽·브랜드·인사이트·날짜 4종·수집자·광고)은 순서 변경·중간 삭제 금지(append가 왼쪽부터 채움). 사람용 칸(메모·활용아이디어·상태 등)은 O열 이후 오른쪽에만 추가 — 기존 행은 push가 절대 덮어쓰지 않으므로 자유롭게 편집 가능.
  • 수집자 이름표 — 새 담당자 PC에서 venv\Scripts\python.exe src\service\trenddb.py set-owner <이름> 1회. 이후 모든 export에 그 이름이 붙는다.
  • 광고 글 처리 — 현재 정책은 "필터하지 않고 광고 칸에 Y 표시만"(is_sponsored 마킹). 광고를 시트에서 빼고 싶으면 sheets_push.py에 필터 조건을 추가하는 방식으로.
  • 여러 PC 협업 — 여러 PC가 같은 시트에 push해도 안전하다(article_id 중복 체크). 각 PC에서 set-owner만 해두면 수집자 칸으로 구분된다.
