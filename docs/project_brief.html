트렌드 모니터링 에이전트

8개 큐레이션 매체에서 매일 자동으로 트렌드를 수집하고, 본문과 이미지를 함께 AI 분석해 한 화면에서 검토하는 사내 모니터링 시스템.

분석 모델
Gemini 3.5 flash (vision)
수집 주기
매일 08:00 · 자동
기본 윈도우
최근 14일 · 60일 가변
결과물
대시보드 · 슬랙 · 터미널 · 교차검증 트렌드
01

무엇을 하는 프로젝트인가

트렌드를 일찍 포착하고 맥락과 함께 본다는 두 가지를 목표로 합니다. 마케터·기획자가 매일 8개 매체를 직접 돌아보지 않아도, 핵심 트렌드 카드만 한 화면에서 검토할 수 있도록 자동화했습니다.

1
수집
9개 소스에서 최근 14일(또는 60일) 글 자동 수집
2
Fetch
각 글의 본문 텍스트 + 이미지 최대 12장 다운로드
3
AI 분석
Gemini가 본문 + 이미지를 함께 보고 20개 필드 추출 (대표 이미지 자동 선정 포함)
4
전달
대시보드 · 슬랙 · 터미널 + 교차검증 트렌드 카드 자동 추출
02

어디서 어떤 정보를 가져오는가

각 매체에서 마케팅팀이 보고 싶다고 지정한 카테고리만 좁혀서 수집합니다. 광범위하게 받지 않고 의도된 범위만 골라옵니다.

캐릿 (careet)요즘뜨는밈 · Z세대 최신근황 · 이주의 유행템유료 미디어 · 시리즈 3개
고구마팜최신 밈과 트렌드RSS · MZ 큐레이션
마케팅레시피한-입 트렌드 카테고리마케터 실행 인사이트
20대연구소뉴스레터 페이지세대 연구 칼럼
뉴닉 고슴이의 비트전체 뉴스레터 (광고 포함)라이프스타일 큐레이션
The Edit (디에디트)STYLE 카테고리 (패션 + 뷰티)에디터 큐레이션
HeyPopPOP-UP 카테고리팝업 · 공간 트렌드
인사이트 (insight)트렌드패션 · 뷰티 · 셀럽 뉴스
구글 트렌드 KR한국 급상승 검색어 (14일 누적)검증용 검색 신호
SINCE_DATE 윈도우(기본 14일 / 옵션 60일) 안의 글만 대시보드에 표시. 그 이전 글은 다음 빌드에서 자동으로 빠집니다. 두 윈도우 모두 빌드 가능 — dashboard.html(14일)과 dashboard_v2.html(60일) 두 결과물 병행 운영.
03

데이터는 어디에 어떻게 저장되는가

한 글의 본문 · 이미지 · 수집 메타 · AI 분석 결과를 같은 글 ID로 4곳에 일관되게 저장합니다.

src/data/
├── articles/                   # 본문 텍스트 (글당 .txt, 6000자)
├── article_images/             # 본문 이미지 (글당 폴더, img_01.png ~)
├── raw/                        # 수집 시 메타 (글당 .json)
├── analysis/                   # AI 분석 결과 (글당 .json) ★
├── collected/                  # 일자별 통합 수집 스냅샷
├── source_cache/               # 소스 모듈별 영구 캐시 (재수집 최소화)
├── article_content_analysis.json   # 분석 통합 인덱스 (전체 검색용)
├── seen.json                   # 글별 첫 포착일 추적
└── dashboard_enrich.json       # 대시보드 카드 보강 캐시

예) 캐릿 1914번 글의 모든 자료는 같은 ID로 4곳에서:

경로내용
articles/1914.txt본문 텍스트 6000자
article_images/1914/img_*.png본문 이미지 12장
raw/1914.json수집 시 메타 (제목·URL·카테고리·태그·발행일)
analysis/1914.jsonGemini 분석 결과 19개 필드 (글당 파일)
04

본문과 이미지를 어떻게 분석하는가

본문 텍스트와 본문 안 이미지들을 한 번에 Gemini 3.5 flash에 보내 종합 분석합니다. 텍스트만이나 이미지만이 아니라, 둘을 함께 보고 한 글의 맥락을 추출합니다.

In
입력
본문 텍스트 6000자
+ 이미지 최대 12장
AI
Gemini 3.5 flash
고정 PROMPT로
19개 필드 추출 강제
Out
출력
JSON 1건
→ analysis/<글ID>.json

분석 결과 20개 필드

메타3개 필드
  • title원본 글 제목 (한글)
  • url원문 URL
  • date원문 기사 발행일 (YYYY-MM-DD)
요약2개 필드
  • one_line_summary1문장 요약
  • full_description2~4문장 종합 설명 (구체적 사례·브랜드·수치 포함)
이미지3개 필드
  • image_by_image[]첨부 이미지를 순서대로 1장씩 묘사
  • image_urls[]다운로드된 이미지 원본 URL (image_by_image와 인덱스 일치)
  • hero_image_index가장 핵심 시각 표현 이미지의 인덱스 — 대시보드 카드 대표 이미지로 자동 사용
분류 · 고정 옵션 중 선택3개 필드
  • content_category패션/뷰티 · 라이프스타일 · F&B · 테크 · 마케팅 · 뉴스 · 라이프 · 기타 중 1개
  • content_format기사 · 인터뷰 · 화보 · 리뷰 · 정보전달 · 이벤트 · 제품홍보 · 데이터분석 · 기타 중 1개
  • is_sponsoredtrue / false — #광고·#제작지원 표기 또는 PR/보도자료 톤이면 true
분위기 · 맥락2개 필드
  • mood_tone콘텐츠 톤·분위기 한 줄
  • scene_setting본문·이미지의 배경·공간 묘사
해석 · 시사점3개 필드
  • sponsorship_note광고 판단 근거 (1문장)
  • marketing_insight마케팅 시사점 (1~2문장)
  • target_audience타깃 독자 (1문장)
본문 추출 · 본문·이미지에서 직접4개 필드
  • topics[]핵심 키워드 5~10개
  • brands_products[]언급된 브랜드·제품
  • people[]등장 인물·셀럽
  • text_in_media[]이미지 안에 보이는 글자 (간이 OCR)
05

결과는 어떻게 보는가

3가지 채널로 결과를 받아볼 수 있습니다. 상황에 맞게 골라 사용합니다.

대시보드
카드형 대시보드 HTML
소스 칩 · 단독 필터 · 교차검증 컨셉 · 검색 신호 + 대표 이미지 자동 적용. 그때그때 즉시 빌드, 기간(14일 / 60일) 가변 지원.
python build_dashboard.py
슬랙
슬랙 다이제스트 전달
팀 채널로 매일 자동 다이제스트 발송. 모바일에서도 핵심 트렌드 카드만 빠르게 훑어볼 수 있고, 댓글로 즉시 공유·논의 가능.
python deliver.py --slack
터미널
CLI · 디지스트 마크다운
개발자·운영자가 터미널에서 바로 확인. docs/review/digest_*.md 마크다운 출력 + 표준출력 요약. 자동화 파이프라인 연계 용이.
python run_daily.py

+ 교차검증 트렌드 자동 추출

매일 자동 실행 후 분석된 글 전체를 다시 메타 분석해, 여러 글에 공통으로 등장하는 핵심 트렌드를 카드 형태로 추출합니다. 결과는 src/data/cross_trends.json으로 저장.

각 트렌드 카드: keyword · what(무엇인지) · why(왜 뜨는지) · sources[](잡힌 매체) · articles[](원문 title · url · source · date). 예) 럭키맥싱(4건, 캐릿·마케팅레시피) · 하이퍼 리얼 일상 아카이빙(6건, 4개 매체) · 그랜플루언서(3건) 등.

06

디벨롭 진행 상황

발견한 한계와 개선 방향. 두 항목은 적용 완료, 하나는 검토중.

① 멀티 토픽 글 분리 로직검토중
  • 현재 문제 : 한 아티클 안에 여러 기사가 묶여 있을 때(예: 캐릿 '이주의 유행템 4개'), 한 개만 대표로 가져오는 경향. 글마다 추출되는 양상이 제각각이라 트렌드 누락 발생.
  • 추천 방안 A : PROMPT에 "multi-topic 글 감지 시 sub_articles[]로 분리 출력" 규칙 추가 — Gemini가 본문 안에서 분리해서 N개 분석 결과로 반환.
  • 추천 방안 B : 본문 H2/H3 + "1. ... 2. ..." 패턴으로 사전 분할 후 각 섹션을 독립 글로 처리. 캐릿·The Edit의 큐레이션 글 구조에 잘 맞음.
  • 추천 방안 C : topics[] · brands_products[]를 trend 추출 단계에서 다시 분리 — 글 단위가 아닌 토픽 단위로 cross_trends 재구성.
② 대표 이미지 선정 로직✓ 적용 완료
  • 채택 방안 : Gemini PROMPT에 hero_image_index 필드를 추가해 "가장 핵심 시각 표현 이미지 1장(배너·CTA·로고 제외)" 자동 선정. 본문 맥락 기반 선정이라 가장 정확.
  • 적용 결과 : 분석 필드 19 → 20개로 확장. build_dashboard.py가 카드 빌드 시 hero_image_index를 읽어 image_urls[idx]로 카드 대표 이미지를 자동 교체.
  • 기존 데이터 백필 : 별도 스크립트(backfill_hero.py)로 기존 91건의 hero_image_index를 일괄 채움. 이미지 다시 보내지 않고 image_by_image[] 묘사 텍스트만 보고 빠르게 선정.
  • 자동화 : run_daily.py에 흐름 추가 — 매일 자동 실행 시 새 글이 분석되면서 hero 자동 적용, 2차 dashboard 빌드까지 자동.
③ 분석 모델 비교 테스트✓ 테스트 완료
  • 테스트 방식 : 동일 글 20건 + 일관성 5건을 Gemini Pro와 Claude Sonnet 4.6 두 모델로 동일 PROMPT 병렬 분석. 5가지 지표 측정.
  • 결과 — 응답 시간 : Gemini Pro 46.8초 vs Claude Sonnet 4.6 49.7초. Gemini 우위.
  • 결과 — 비용(20글) : Gemini Pro $0.50 vs Claude Sonnet 4.6 $1.10 (2.2배). Gemini 우위.
  • 결과 — 카테고리 일관성 : 두 모델 모두 100% 동률. 같은 글 2회 분석 시 카테고리 분류가 항상 일치.
  • 의사결정 : 운영 모델은 Gemini 3.5 flash(현행) 유지가 합리적. 글별 상세 비교 + Jaccard 유사도 등은 docs/model_compare.html 참조.
